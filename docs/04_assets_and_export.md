# 资产与导出

资源库 .tres 是索引；同名 .assets 目录按 bullets、barrages、bosses、waves、levels、obstacles 保存独立资产。游戏索引引用战斗库，并把 player、world 保存为独立资源。Resource 保存配置，PackedScene 保存节点结构，Script 保存能力算法；生命、计时、目标和冷却只保存在运行实例。

制作保存经过 AssetStore：先序列化与检查全部文件，再提交，索引最后写入；失败回滚，磁盘修订冲突明确报错。所有权文件 .stgmaker_assets.json 记录管理范围。共享声明和手写脚本不会被资产保存覆盖；删除索引项也不会自动清扫可能被外部使用的文件。

项目当前只读取格式 12。现有制作库、共享场景及两个游戏入口已在交付时一次性转换。将来改变格式时，应另做工程外的数据转换，不能在 runtime、文档读取或构建入口加入隐式历史回退。

构建入口 addons/stg_maker/build/compiler.gd 根据游戏地图与主角能力收集资源闭包，再复制选中配置。未选中的坏草稿不影响构建，选中配置与源库的可编辑曲线/参数隔离。脚本声明引用与相对静态依赖都会进入构建检查。

project_builder.gd 生成独立 Godot 工程，包含 stg 运行框架、具体游戏表现及选中内容和脚本依赖。addons、tools、tests 不进入成品；运行代码若反向依赖这些目录，构建失败。再次构建只更新已登记的生成文件。

独立工程中的 Run Game.cmd 会先执行首次导入，再启动游戏。Windows 游戏包还需要与引擎版本匹配的导出模板。可以通过游戏页面构建，也可以使用 tools/build_game.gd。

交付验证包括当前资源格式、完整引用、脚本加载、生命周期、真实编辑器和独立导出。最终画面、轨迹与节奏的制作效果由你按现有内容检查。
