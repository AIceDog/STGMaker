### 第一版采用的明确规则

- 前摇 / 后摇属于每颗弹体，开始延迟属于整次招式。前摇不移动、不判伤；自然结束后停止运动和判定，再后摇。
- 发射动画适配前摇；无前摇时按原动画时长播放。后摇动画适配后摇；命中动画独立收尾，不触发自然消失。
- 轮间隔按相邻轮第一批起点计算，允许轮次重叠。完整轮规划与每轮瞄准在该轮开始取样。
- 末批保留余数。排列与逐颗螺旋使用完整轮序号，分组只安排时间。
- 拖尾长度采用路径距离，0 表示只按每段寿命限制，宽度仍在素材中编辑。
- 召唤前摇后出现，入场结束才启动敌人行为；存活上限包含前摇与入场。
- 素材保存通用帧动画与粒子，招式保存额外音效 / 事件特效，同一表现不需要重复配置。
- 脚本发射模块继续自行安排轮内时刻，不叠加内置分组调度，第一版界面明确说明此边界。

这些是第一版可运行、可反馈的具体取法，后续根据制作体验调整，不代表所有高级控件已定案。

## 原始设计记录

以下保留最初需求及核对过程。当时标注为待定、尚未确认的条目，现以顶部实施状态和当前功能说明为准。

## 子弹素材

### 基础属性布局

- 外观与碰撞继续同页对照编辑。
- “大小”“局部偏移”等标签必须横排，不能在窄面板或大字号下逐字换行为竖排。
- 大小的 X/Y 输入同行；局部偏移的 X/Y 输入同行。
- 基础属性直接展开，不新增折叠；不恢复在画面编辑外形、碰撞的按钮或几何拖拽代码。

### 子弹的贴图和动画

- 几何外形与贴图外形明确区分；只有贴图类子弹提供贴图动画配置。
- 选择“贴图”后，直接在“外观与碰撞 → 外观”里配置动画，保留大小、局部旋转、局部偏移、颜色等基础参数。
- 贴图选择与动画配置需要统一职责，避免并列存在两份重复的外观配置。
- 用户期望使用 GIF 动图提供表现。直接导入 GIF 尚不是当前功能；需要在后续实现中处理导入与帧时长。
- 用户列出的四类表现为：刚发射、运行中、碰撞/命中、未命中时的正常消失。
- 单张静态图仍应能表达普通贴图子弹，不强制制作多帧动画或填写全部阶段。

### 子弹粒子

- 各种外形的普通子弹都可以有粒子，包括圆形、多边形和贴图外形。
- 分为刚发射的粒子、运行中的粒子、碰撞/命中后的粒子。
- 粒子资源与贴图帧动画是不同配置，不能因为几何外形没有贴图动画就禁用粒子。

### 激光

- 当前需求不提供激光粒子配置。
- 激光保留外观、独立碰撞和阶段表现。
- 阶段为攻击前摇、攻击中、攻击后摇。
- 子弹/炮弹与激光共用在指定位置生成攻击的基础能力；不要因此复制两套运行逻辑。
- 几何激光的阶段变化与贴图逐帧动画应分清：几何可以调整宽度、缩放、透明度等表现；贴图激光可再使用贴图帧动画。此处是技术解释，具体控件尚待实施。

### 拖尾

- 用户尚未确定拖尾的最终制作界面，先保留讨论状态。
- 已向用户解释当前实现：记录发射者实际走过的路径，分段绘制，每段独立计时、碰撞和淡出，瞬移时断开。
- 讨论建议：普通烟雾/火花尾巴可以归入运行粒子；有持续时间和伤害判定的路径带适合作为独立拖尾素材。该区分尚不代表用户已确认所有界面细节。

## 招式库：按招式类型显示不同 UI

招式类型包括普通子弹、激光、拖尾、召唤敌人。普通子弹已经提出较详细的分区；激光、拖尾、召唤敌人已补充职责和模式，详细控件仍待细化，不能直接复制普通子弹的全部控件。

### 普通子弹页面的三个职责

| 区域 | 职责 |
| --- | --- |
| 子弹节奏 | 控制前摇时间、后摇时间，并驱动子弹素材中对应的阶段动画 |
| 发射节奏 | 保留当前发射节奏能力；容纳发射实现、齐射/分组方式以及组间时间间隔 |
| 弹道 | 出生位置与排列、发射数量与方向，以及完整的飞行过程 |

上表保留用户提出的分区意图。用户同时提出“发射数量与方向”是否与发射节奏、弹道重叠的问题，要求每个 UI 的职责明确且不重复；数量的最终归属尚待确认，见文末核对建议。

### 发射节奏与分组发射

- “发射实现”放进“发射节奏”区域，不再作为独立的同级区域。
- 发射方式包含齐射和分组发射。
- 齐射：一轮的子弹同时发出。
- 分组：把同一轮的全部子弹按每组数量分成多次发出，组与组之间有可调整的时间间隔。
- 每组 1 颗，即逐颗分批发射。
- 每组 3 颗，即每次同时发出 3 颗，直到本轮全部子弹发完。
- 举例说明：一轮 12 颗、每组 3 颗，可分 4 次发完；如果组间隔 0.1 秒，则组相对本轮开始的发出时刻为 0、0.1、0.2、0.3 秒。此例用于说明用户提出的规则。
- 这是同一发射规则中一轮内部的分组调度，不是恢复过去由多套独立发射规则组成的“发射组”架构。
- 多个不同招式之间的顺序、等待与并行，继续由敌人行为流程组织。

### 弹道

- 出生位置与排列归入弹道。
- “攻击原点”改名为“子弹生成位置”。激光、召唤等页面应使用相应对象的名称，不能一律写成子弹。
- “位置偏移”标签横排，X/Y 输入同行，不能逐字换行为竖排。
- 用户原提议将一轮的发射数量与各颗弹体的方向归入弹道，同时要求核对数量、发射节奏与弹道的职责是否重叠；最终分区尚未确认。
- 暂不提供“轮次变化与随机”功能，当前希望敌人攻击节奏规律。
- 飞行过程放在弹道里，属于高级弹道；用户后续专门设计，当前不擅自补齐其详细控件与规则。
- 分批螺旋发射中的螺旋/旋转规则由弹道控制；分组调度只负责发出的批次和时间，不能再维护一套独立的弹道规则。

### 激光招式

- 职责划分与普通子弹类似，但弹道提供二选一的模式：在指定位置直接生成激光，或按普通子弹的弹道发射、运动。
- 两种模式不能同时生效；各模式的详细参数、阶段表现与时序仍需统一。

### 拖尾招式

- 不需要照搬普通子弹的全部弹道设置，主要关注拖尾有多长。
- “长度”具体表示路径距离还是保留时间，用户尚未明确；不能擅自把两者视为同一个参数。
- 拖尾素材的最终制作界面仍处于讨论状态。

### 召唤敌人招式

- 召唤敌人是单独一类招式，与子弹、激光、拖尾并列。
- 提供二选一的模式：在指定位置直接召唤，或将敌人发射出去。
- 支持召唤特效和前摇时间。
- 发射出去期间的移动，以及何时由敌人自身行为流程接管，尚待统一。

## 实施前需要统一的细节

这些是尚未定案的细节，不是本次要求用户立即回答的问题，也不能擅自写成已确认规则。

- 上一轮的发射/运行/命中/自然消失四类表现，与本轮所说前摇/后摇动画如何对应。

- 一轮总数不能被每组数量整除时，最后一组如何处理。
- 分组发射时，出生排列和螺旋方向按完整轮中的弹体序号还是其他规则计算；应保持同一套弹道职责。

- 每轮数量的唯一编辑入口，以及发射节奏、基础弹道、高级弹道的最终控件归属。
- 暂不提供“轮次变化与随机”后，现有参数如何处理，以及如何保留用户明确提出的规律螺旋弹道。
- 激光两种生成模式的详细控件与阶段规则。
- 拖尾长度的单位、保留时间和淡出时间之间的区别。
- 召唤敌人发射阶段与敌人自身移动、行为流程的接管时机。

## 本轮核对建议（尚未确认）

以下为核对时提出的建议，不代表用户已同意，也不代表功能已经实施。

### 数量、时间与空间分别编辑

建议拆开“发射数量与方向”这个混合区域，每个参数只保留一处可编辑入口：

| 区域 | 建议职责 |
| --- | --- |
| 子弹节奏 | 前摇、后摇及其对应阶段表现；作用于整次招式还是每颗弹体，仍需明确 |
| 发射节奏 | 每轮数量、轮数、轮间隔、齐射或分组、每组数量、组间隔，以及发射实现 |
| 基础弹道 | 生成位置与偏移、出生排列、初始方向与角度分布、规律螺旋等空间规则 |
| 高级弹道 | 飞行中的速度、转向与阶段行为；等待用户后续专门设计 |

- 每轮数量建议放入发射节奏，方向放入弹道。弹道排列与预览读取同一份数量，不再提供第二个数量输入。
- 分组调度只安排同一轮弹体的发出时刻；不能重新定义数量分布、方向或飞行算法。
- “规律”不等于所有方向固定：移除随机能力时，不应连同用户明确要求的规则螺旋一并删除。具体保留哪些旋转参数仍待确认。

### 类型与运行职责

- 建议先选择招式类型，再选择其引用的素材或敌人资产。召唤敌人引用敌人定义，不需要伪装为子弹素材，也不应重复配置敌人的外观、碰撞和完整 AI。
- 激光、召唤的“指定位置直接生成”描述生成方式，建议不因此跳过前摇或相关表现；具体时序仍待确认。
- 激光的弹道模式建议理解为激光整体按弹道运动。激光自身伸长、收缩属于表现或专门能力，不应未经确认再增加一种生成模式。
- 拖尾“有多长”建议使用路径距离；保留多久、如何淡出分别处理。外观宽度等属性继续由素材负责，避免在招式中重复编辑。
- 召唤发射建议使用明确的入场移动阶段，然后交给敌人行为流程；同一时刻由一个控制方决定移动，避免招式弹道与敌人 AI 同时修改位置。
- 整次招式的前摇/后摇与每颗弹体的出生/消失动画不能直接画等号，应先明确动画播放对象和起止事件，再决定控件及触发规则。
